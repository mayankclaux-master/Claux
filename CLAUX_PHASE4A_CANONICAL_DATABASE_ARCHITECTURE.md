# CLAUX Phase 4A — Canonical Database Architecture Map

**Date:** 2026-05-23
**Architecture:** CLAUX V1 HYBRID (AI intelligence + Human execution)
**Target Scale:** 1000 clients, 100k+ tasks

---

## ARCHITECTURE PRINCIPLES

1. **Tenant Isolation:** Every data table must have tenant_id with proper RLS
2. **Simplicity:** No over-engineering, no speculative features
3. **Performance:** Optimized for dashboard queries at 1000-client scale
4. **Deterministic:** No queues, no distributed systems, no complex concurrency
5. **Production-Safe:** Basic integrity constraints, no exotic patterns

---

### B. RUNTIME TABLES (Agent Execution)

#### agent_executions
**Purpose:** Canonical agent execution records
**tenant_id:** TEXT
**RLS:** Yes
**Indexes:** 
- tenant_id
- tenant_id, status
- tenant_id, agent_name
- tenant_id, created_at DESC
**Constraints:** 
- CHECK (retry_count <= max_retries)
- CHECK (status = 'completed' AND completed_at IS NOT NULL OR status != 'completed')
- CHECK (status = 'failed' AND failed_at IS NOT NULL OR status != 'failed')
- CHECK (status = 'running' AND started_at IS NOT NULL OR status != 'running')
- CHECK (total_cost >= 0)
- CHECK (total_tokens >= 0)
**Purpose:** Track all agent executions for dashboard visibility

#### agent_tasks
**Purpose:** Agent task execution records within executions
**tenant_id:** TEXT (via execution_id)
**RLS:** Yes
**Indexes:**
- execution_id
- execution_id, status
- execution_id, step_order
**Constraints:**
- CHECK (retry_count <= max_retries)
- CHECK (status = 'completed' AND completed_at IS NOT NULL OR status != 'completed')
- CHECK (status = 'failed' AND failed_at IS NOT NULL OR status != 'failed')
- CHECK (status = 'running' AND started_at IS NOT NULL OR status != 'running')
- CHECK (duration_ms IS NULL OR duration_ms >= 0)
**Purpose:** Track individual agent steps for execution timeline

#### agent_events
**Purpose:** Agent event correlation and causation tracking
**tenant_id:** TEXT
**RLS:** Yes
**Indexes:**
- tenant_id
- tenant_id, correlation_id
- correlation_id, causation_id
**Constraints:**
- UNIQUE (correlation_id, causation_id)
**Purpose:** Track event causality for execution forensics

#### agent_logs
**Purpose:** Agent execution log entries
**tenant_id:** TEXT (via execution_id)
**RLS:** Yes
**Indexes:**
- execution_id
- execution_id, log_level
- execution_id, created_at DESC
**Constraints:** None
**Purpose:** Store execution logs for debugging and transparency

## RLS POLICY STANDARDIZATION

### Standard Policy Pattern

```sql
-- Enable RLS
ALTER TABLE [table_name] ENABLE ROW LEVEL SECURITY;

-- Select policy
CREATE POLICY "Users can view own tenant [table]" ON [table_name]
  FOR SELECT USING (tenant_id = auth.jwt() ->> 'sub');

-- Insert policy
CREATE POLICY "Users can insert own tenant [table]" ON [table_name]
  FOR INSERT WITH CHECK (tenant_id = auth.jwt() ->> 'sub');

-- Update policy
CREATE POLICY "Users can update own tenant [table]" ON [table_name]
  FOR UPDATE USING (tenant_id = auth.jwt() ->> 'sub');

-- Delete policy (if applicable)
CREATE POLICY "Users can delete own tenant [table]" ON [table_name]
  FOR DELETE USING (tenant_id = auth.jwt() ->> 'sub');
```

### RLS Coverage

All active tables will have RLS enabled with the standard policy pattern.
